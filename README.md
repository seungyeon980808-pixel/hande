## 최종적으로 해결한 문제

학교에서는 담당자가 여러 교사에게 양식을 보내고, 각 교사가 파일을 내려받아 작성한 뒤 이름을 바꾸어 메신저로 다시 보내는 일이 반복됩니다. 담당자는 수십 개의 첨부파일을 내려받아 폴더에 정리하고 미제출자를 따로 확인해야 합니다. 여러 스프레드시트를 수작업으로 합치는 과정에서는 누락과 최신본 혼동도 생깁니다. Google 스프레드시트 같은 외부 서비스에 학교 문서나 개인정보를 저장하기 어려운 상황도 있습니다.

### 어떻게 풀었나요?

수합의 정석은 담당자가 취합 요청을 한 번 만들고 공통 제출 링크를 공유하면, 교사가 로그인 없이 자신을 선택하여 HWP/HWPX·웹 표·XLSX 자료를 작성하고 제출할 수 있게 합니다. 담당자는 별도 관리 링크에서 미작성·작성 중·제출·재제출 현황과 모든 제출 버전을 확인합니다.

한글 문서는 rHWP 편집기에서 작성하며 교사명과 부서명을 자동 치환합니다. 지정 필드 공동작성에서는 담당자가 HWPX의 누름틀마다 담당자를 배정하고, 참여자가 자신의 필드만 원본 양식 안에서 편집하게 합니다. 웹 표는 열 형식과 필수값을 통제한 채 여러 사람의 최신 제출을 하나의 XLSX로 합칩니다. 임의 형식의 엑셀 파일은 원본을 보존하고 최신 제출을 ZIP으로 제공합니다.

## 핵심 기능

- 한글 문서, 웹 표, 엑셀 파일 중 업무에 맞는 취합 유형 선택
- 공통 제출 링크와 담당자 전용 관리 링크 자동 생성
- 로그인 없이 이름과 부서를 검색하여 제출자 선택
- HWPX의 `{{교사명}}`, `{{부서명}}` 자동 치환과 rHWP 기반 문서 작성
- HWPX 누름틀별 담당자·필수 여부·순서 지정 및 담당 필드만 편집하는 공동작성
- 웹 표의 글자·숫자·날짜·단일 선택 열, 필수값, 선택지와 행 추가·삭제 지원
- 웹 표·한글 문서 자동 임시저장과 XLSX 임시 업로드
- 최종 제출과 재제출을 덮어쓰지 않고 버전별로 보존
- 미작성·작성 중·제출·재제출 현황 및 제출 이력 확인
- 웹 표 최신 제출을 결과·제출 현황 시트가 든 XLSX로 통합
- 엑셀 파일의 교사별 모든 버전 다운로드와 최신 제출 ZIP 생성
- 업무 매뉴얼 통합 검색, 개인 툴박스, 나이스 시간표 조회

## 사용 흐름과 사용 방법

1. 담당자가 새 취합 요청에서 제목, 마감, 대상 교사와 취합 유형을 정합니다.
2. 한글 문서는 일반 제출 또는 지정 필드 공동작성을, 엑셀은 웹 표 입력 또는 파일 제출을 선택합니다.
3. 필요한 HWP/HWPX/XLSX 양식이나 웹 표 열 구조를 등록합니다.
4. 생성된 공통 제출 링크를 대상 교사에게 공유하고 담당자용 관리 링크는 별도로 보관합니다.
5. 교사는 로그인 없이 이름과 부서를 선택하고 문서·표·파일을 작성합니다.
6. 작성 중 내용은 임시저장하고, 확인 후 최종 제출합니다. 수정이 필요하면 재제출할 수 있습니다.
7. 담당자는 관리 화면에서 상태와 버전을 확인하고 통합 XLSX, 최신 ZIP 또는 취합 HWPX를 내려받습니다.

- 사용 환경: PC 웹
- 사용 조건: 계정 없이 무료로 사용할 수 있습니다.
- macOS: `실행하기.command`를 더블클릭합니다.
- Windows: Node.js 22 이상이 설치된 환경에서 `실행하기-Windows.bat`를 더블클릭합니다.
- 같은 학교망의 다른 기기에서는 실행 화면에 표시되는 네트워크 주소로 접속합니다.

## 기술 스택과 실행 방법

- **화면**: Next.js App Router, React, TypeScript, Tailwind CSS
- **서버·백엔드**: Next.js Route Handlers, Node.js
- **문서 편집**: 자체 실행하는 rHWP Studio
- **엑셀 생성**: ExcelJS
- **저장소**: 개발·시연 단계에서는 로컬 JSON과 `storage/private`; PostgreSQL 전환 구조 포함
- **AI**: 개발·검토 과정에서 사용; 앱의 핵심 취합·판단 과정에는 생성형 AI를 사용하지 않음
- **배포**: macOS·Windows 자체 실행, 같은 네트워크에서 공유

### 폴더 구조

```text
drizzle/                 # PostgreSQL 마이그레이션
public/                  # 정적 파일
src/
  app/                   # 화면과 Route Handlers
  components/            # 공용 UI와 문서 편집 구성요소
  db/                    # 데이터베이스 스키마
  lib/                   # 저장·문서·엑셀 로직
vendor/
  rhwp-studio/           # 자체 실행 HWPX 편집기
storage/private/         # 제출 파일, Git 제외
.data/                   # 개발 메타데이터, Git 제외
```

### 설치와 실행

Node.js 22 이상에서 실행합니다.

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다. rHWP Studio는 함께 실행되며 기본적으로 7700번 포트를 사용합니다.

나이스 시간표 연동 시 `.env.example`을 `.env.local`로 복사하고 다음 환경변수의 값을 설정합니다. 값은 저장소에 커밋하지 않습니다.

```text
NEIS_API_KEY
NEIS_ATPT_OFCDC_SC_CODE
NEIS_SD_SCHUL_CODE
NEXT_PUBLIC_RHWP_STUDIO_URL  # 별도 내부 주소를 사용할 때만
```

검증 명령은 다음과 같습니다.

```bash
npm test
npm run lint
npm run build
```

## 작동 범위와 한계, 다음 계획

### 현재 작동 범위

- HWP/HWPX, 웹 표, XLSX를 이용한 교사 대상 업무 취합
- 제출·관리용 난수 링크, 버전별 불변 보관, 임시저장과 재제출
- 같은 PC 또는 같은 학교망의 자체 실행 환경
- 웹 표 최신 제출의 XLSX 통합과 파일 제출의 ZIP 묶음

### 현재 한계

- 이름 선택은 사용성을 위한 신뢰 기반 식별이며 강한 본인 인증이 아닙니다.
- 다른 기기에서는 기존 브라우저의 임시저장본을 자동 복구할 수 없습니다.
- 임의 형식의 XLSX는 시트와 셀 구조가 달라 자동 병합하지 않습니다.
- XLSM, 구형 XLS, 암호화된 XLSX는 지원하지 않습니다.
- 복잡하게 분할된 HWPX XML이나 임의 HWP 파일은 자동 치환 호환성 검증이 더 필요합니다.
- 앱 자체에는 학교 내부망 IP 제한이 없으므로 운영 시 방화벽 설정이 필요합니다.
- PostgreSQL 배포 구조는 포함되어 있지만 현재 시연본의 데이터는 로컬 파일에 저장됩니다.

### 다음 계획

- 로컬 파일 저장소를 PostgreSQL 어댑터로 교체하고 동시 제출을 부하 테스트합니다.
- 학교 계정 SSO 또는 내부 인증을 추가합니다.
- HTTPS, 허용 IP 대역, 백업·복구, 로그 보존 정책을 마련합니다.
- 실제 개인정보 없이 HWPX 호환성과 Windows·학교망 환경을 확대 검증합니다.
- 접근성, 모바일 대응, 관리 화면의 검색·필터 기능을 개선합니다.

## 교육 현장에서 사용할 때의 주의사항

- 실제 적용 전 소속 기관의 개인정보·보안 정책을 확인합니다.
- 저장소와 시험 데이터에 실제 학생·교직원 정보나 제출 문서를 넣지 않습니다.
- 관리 링크는 제출 링크와 분리하여 담당자만 보관합니다.
- 이름 선택만으로 본인 인증이 되지 않으므로 민감정보 취합에는 학교 계정 인증을 추가해야 합니다.
- 외부 공개 서버보다 학교가 관리하는 PC·내부 서버에서 실행하고 3000·7700번 포트의 접근 대역을 제한합니다.
- 제출 전 교사가 내용을 직접 확인하고, 담당자는 자동 취합 결과를 원본과 대조합니다.
- 기기나 네트워크 문제로 제출하지 못한 사용자를 위한 대체 제출 방법을 함께 안내합니다.

### 교육적 태도 점검

- 프로그램이 평가·추천·피드백을 대신 확정하지 않습니다.
- 학생이나 교사의 생각을 대신 생성하지 않습니다.
- 저장·공유·최종 제출 전에 사용자가 내용을 직접 확인할 수 있습니다.
- 제출 현황은 업무 지원에만 사용하고 개인 평가나 감시 자료로 사용하지 않습니다.
- 접근이 어려운 사용자를 위해 파일 제출 등 대체 경로를 마련해야 합니다.

## 교사 개발자 윤리 자가점검

- **최소 수집**: 취합 목적에 필요한 이름·부서·제출 내용만 다루도록 설계했습니다.
- **목적 제한**: 제출 데이터와 현황을 요청한 학교 업무의 취합 외 목적으로 사용하지 않습니다.
- **사람의 확인**: 프로그램은 취합과 정리를 돕고 최종 판단과 제출 책임은 사용자에게 남깁니다.
- **투명성**: 임시저장, 최종 제출, 재제출과 버전 보존 상태를 화면에서 구분합니다.
- **접근 통제**: 제출 링크와 관리 링크를 분리하고 관리 토큰은 서버에 해시로 저장합니다.
- **데이터 보호**: 파일은 공개 폴더 밖에 저장하며 확장자·크기·경로를 검사합니다.
- **한계 공개**: 이름 선택이 강한 인증이 아니며 내부망 제한과 운영 보안이 별도로 필요함을 밝힙니다.
- **삭제·보존 정책**: 시연을 넘어 실제 운영하기 전에 기관 기준에 맞는 보존 기간과 삭제 기능을 확정해야 합니다.
